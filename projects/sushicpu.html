Project

sushiCPU

A fully pipelined 5-stage RISC-V (RV32I) processor, designed and written from scratch in Verilog.

VerilogRISC-V

What it is

sushiCPU is a from-scratch implementation of the RV32I base integer instruction set in Verilog. I started with the fundamentals (module hierarchy, always blocks, blocking vs. non-blocking assignment, avoiding unintended latch inference) and built up to a complete processor. I first built a working single-cycle core, then extended it to a 5-stage pipeline.

  • Core datapath: ALU, register file, immediate generator, control unit, branch unit, PC register, and instruction/data memory.
  • Verification: validated the single-cycle design with a 17-instruction test program covering arithmetic, memory, branch, and jump instructions.
  • Pipelining: added a forwarding (bypass) unit for data hazards and hazard detection that stalls on load-use dependencies.
  • Design details: a 4-way writeback mux to support the different result sources, a dedicated alu_src_a select so AUIPC can use the PC as an ALU operand, and clearing the LSB of JALR targets as the spec requires.

What I learned

  • Data hazards are the hard part of pipelining. The datapath itself was manageable, but read-after-write dependencies between in-flight instructions took the most careful reasoning. Forwarding solved most of them, and load-use cases still needed a stall.
  • Hardware thinking differs from software thinking. Everything runs in parallel, and small choices like blocking vs. non-blocking assignments or an incomplete if/case can silently synthesize latches or race conditions.
  • The ISA spec is full of small details that matter. Things like AUIPC needing the PC as an operand and JALR clearing the target's low bit only show up when you implement the instructions and check each one against the spec.
  • Building the simple version first made the pipeline tractable. Getting a verified single-cycle core before adding stages meant I could tell pipeline bugs apart from datapath bugs.
  • It connects to architecture coursework in a concrete way. Concepts like hazards, forwarding, and control signals became things I had to debug rather than definitions to memorize.
