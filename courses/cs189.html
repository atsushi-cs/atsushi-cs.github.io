sushiGPT

A GPT-2-scale language model built from scratch in PyTorch, from tokenizer to instruction-tuned chatbot.

PythonPyTorchMPSGoogle Colab (T4)

What it is

sushiGPT is a full GPT-style language model I built from the ground up, following Andrej Karpathy's Zero to Hero curriculum, to understand every layer of the stack instead of treating it as a black box. The project covers the whole LLM pipeline:

  • Tokenization: implemented byte-pair encoding from scratch, including a basic tokenizer and a regex-based tokenizer in the style of GPT-2.
  • Architecture: wrote the full decoder-only transformer, using GPT-2 small dimensions (768 embedding size, 12 heads, 12 layers, 1024 context, 50,257-token vocabulary).
  • Pretraining: trained on Tiny Shakespeare locally, using Apple's MPS backend on my MacBook.
  • Loading real weights: manually ported pretrained GPT-2 weights into my own implementation, handling the Conv1D weight transposes and splitting the fused Q/K/V matrices.
  • Supervised fine-tuning: fine-tuned on the Alpaca instruction dataset using prompt loss masking so the model learns only from response tokens. This ran on a T4 GPU in Google Colab.

What I learned

  • Building it end to end changed how I think about LLMs. Writing the tokenizer, attention, and training loop myself made concepts like context length, weight layout, and loss masking concrete instead of abstract.
  • Loading pretrained weights is a debugging exercise in details. Matching GPT-2's checkpoint format meant working out transposed Conv1D weights and splitting the combined attention projection. A shape mismatch or a silent transpose error produces a model that runs but outputs garbage.
  • Fine-tuning quality depends on what you train on. Masking the prompt tokens in the loss kept the model focused on producing good responses rather than memorizing instructions.
  • Overfitting and repetition are fixable. Small-data training led to repetitive output, which I addressed with temperature sampling, top-k sampling, and earlier stopping.
  • Compute constraints shape workflow. I used local hardware for pretraining and moved to a cloud GPU when fine-tuning outgrew it.
